# Owner-only access: design

**Goal:** close both environments (staging, prod) to the public. Only the owner, from an
allowlisted IP, can use them; post-deploy smoke tests keep running against the live URLs.

## Decisions

| Question | Choice | Why |
|---|---|---|
| How the owner proves identity | IP allowlist | No login flow; owner-only demo |
| Enforcement point | CloudFront Function (viewer request), not AWS WAF | WAF for CloudFront must live in us-east-1 and costs ~$5+/month per ACL; a function sees `event.viewer.ip`, runs in the existing stack, and is nearly free |
| CI access | Secret bypass header `x-egm-smoke-token` | GitHub runner IPs are shared and unpredictable |
| Where the allowlist lives | CloudFront KeyValueStore (one per environment) | Updates take seconds with no deploy, and the owner's IP never enters this public repo or CI logs |

## Architecture

```
You / CI --> CloudFront --> [edge function: allow?] --> S3 (SPA)
                                   |                \-> API Gateway -> Lambda -> DynamoDB
                                   v                          ^
                              403 Forbidden          rejects requests without
                                                     CloudFront's secret header
```

- **Edge function** on every cache behavior (default and `/api/*`). It allows the request
  when the store has key `ip:<viewer ip>`, or when the `x-egm-smoke-token` header equals
  the store's `smoke-token` value. Otherwise it returns `403 Forbidden`. It fails closed:
  an empty store, missing key, or lookup error means 403.
- **KeyValueStore** per environment, created by CDK, empty at creation; data is set by the
  owner's script, never by CDK or CI.
- **Origin lock.** HTTP APIs have no resource policies, and the default `execute-api`
  endpoint cannot be disabled while CloudFront uses it as the origin. CloudFront adds an
  `x-origin-verify` header to API origin requests; the Lambda returns 403 when it is
  missing or wrong. The value is a Secrets Manager secret generated by CDK and passed to
  CloudFront and the Lambda at deploy time via a dynamic reference.
- **IPv6 disabled** on both distributions, so the allowlist only needs IPv4.

Not protected against: other people behind the owner's IP (shared office Wi-Fi, carrier
NAT). That is inherent to IP allowlisting.

## Secrets

| Secret | Lives in | Set by |
|---|---|---|
| Owner IPs | KeyValueStore keys `ip:<address>` | Owner, via `npm run access` |
| Smoke token (per environment) | GitHub environment secret `SMOKE_TOKEN` and the store key `smoke-token` | Owner, via `npm run access` (never printed) |
| Origin-verify value | Secrets Manager (CDK-generated) | CDK |

## Owner script: `npm run access`

Uses the `egm-admin` AWS profile.

- `allow-me`: detect the current public IPv4 and add it to both environments.
- `list` / `remove <ip>`: show or delete allowlist entries.
- `rotate-smoke-token <env>`: generate a token and write it to GitHub and the store
  without printing it.

## CI

- Smoke tests send `SMOKE_TOKEN` as `x-egm-smoke-token` (required in CI).
- A new smoke test requests the site without the token and expects 403, so every deploy
  proves the lock is on.
- E2E tests run locally without CloudFront: the Lambda skips the origin check when its
  environment variable is unset. An infra test asserts the variable is set in both
  deployed stacks, so it cannot fail open there.

## Rollout (two PRs)

Shipping the stores and the lock together would lock out the smoke tests (empty store)
and trigger a prod rollback to the unlocked version.

1. **PR A:** create the KeyValueStores and the origin-verify secret. The function is not
   attached yet; the sites stay public. After deploy, the owner runs `allow-me` and
   `rotate-smoke-token staging|prod`.
2. **PR B:** attach the function, enable the Lambda origin check, disable IPv6. Smoke
   passes with the token; `prod-good` moves to the locked version, so later rollbacks stay
   locked.

## Testing

- Unit: edge function (allowed IP, right token, wrong token, empty store, lookup error)
  and Lambda origin check (missing, wrong, correct header; unset variable for local).
- Infra: function on both behaviors, IPv6 off, origin header configured, origin-check
  variable set on the Lambda.
- Smoke: anonymous request gets 403.

## Cost

About $1/month: two Secrets Manager secrets; CloudFront Functions and KeyValueStore reads
are negligible at this traffic.
